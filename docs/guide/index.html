Clang Tracer Guide

Install the tracer, capture a C++ call, and build reusable probes and analysis workflows.

Clang Tracer user guide

Clang Tracer attaches to a running Linux x86-64 C++ process. A session identifies an attachment and a probe runs a C++ observer when a selected function is called. PRE runs before the original call and POST runs after a normal return. The injected agent sends events to the server, where clients can stream, retain, or record them.

Interface Use it for
clang-tracer-repl Explore a local process, prepare and install probes, record and analyze events in C++.
clang-tracer-console Control a server interactively through the Python client.
clang-tracer Run one tracing operation at a time in a shell or script.
clang_tracer.Client Automate tracing from Python. See the developer guide.

Start with the first probe below, then use the command reference and tutorials.

Install and check the tools

On the c++17 branch, the native Linux x86-64 backend builds as C++20 and the native REPL builds as C++17. Use matching LLVM/Clang 21 or 22 development libraries, CMake, Protobuf, gRPC and SQLite development packages. The injected agent needs compatible runtime libraries on the target machine. Build the target with debug info, preserve its ELF or separate debug files, and use a compiler and ABI supported by the agent. The tracer must have permission to attach to the target under the host's Linux tracing policy.

From the repository root, configure, build and install into a user-owned prefix. Replace the toolchain path with the matching LLVM/Clang installation.

bash
./build-rhel.sh --toolchain-root /opt/llvm-21 --build-dir build-rhel \
  --prefix "$HOME/.local/clang-tracer" --examples
./deploy-rhel.sh --build-dir build-rhel
export PATH="$HOME/.local/clang-tracer/bin:$PATH"
clang-tracer-server --help
clang-tracer-repl --help

For a split LLVM installation, CMake options, staging, tarball and RPM packaging, see Build and deploy on RHEL-compatible Linux. For GCC 8.5 SDK targets, use the SDK compatibility build. If you already have the native package, put its binary directory on PATH and run the two help commands. The server finds its matching installed agent automatically. The native REPL starts and owns a private server unless you specify an endpoint.

The Python client is installed separately. Use Python 3.12 or newer. Install from the repository or replace ./python with your distribution's wheel.

bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install ./python
clang-tracer-console --help

Create a target and a basic probe

Work in a scratch directory that both terminals can access. Save this as target.cpp. The target prints its PID and waits for Enter so you control when the probe fires. When the SDK headers expose PR_SET_PTRACER, the demo requests permission for a tracer in the second terminal.

cpp
#include <cstdio>
#include <poll.h>
#include <sys/prctl.h>
#include <unistd.h>

__attribute__((noinline)) int add(int a, int b) { return a + b; }

int main() {
#ifdef PR_SET_PTRACER
  if (prctl(PR_SET_PTRACER, PR_SET_PTRACER_ANY, 0, 0, 0) == -1) {
    perror("PR_SET_PTRACER");
    return 1;
  }
#endif
  std::printf("PID %ld | press Enter to call add, Ctrl+C to exit\n",
              static_cast<long>(getpid()));
  std::fflush(stdout);

  pollfd input{STDIN_FILENO, POLLIN, 0};
  while (true) {
    // Check stdin without blocking in a read while the tracer attaches.
    if (poll(&input, 1, 0) > 0) {
      char byte;
      if (read(STDIN_FILENO, &byte, 1) != 1) break;
      if (byte == '\n') {
        std::printf("add(20, 22) = %d\n", add(20, 22));
        std::fflush(stdout);
      }
    }
    usleep(20'000);
  }
}

Save the observer as hook.cpp. Specialize Interceptor<int(int, int)> to match the return and parameter types of add. Clang Tracer supplies the primary template and Call, so the callback can read typed arguments and results directly.

cpp
template <>
class Interceptor<int(int, int)> {
public:
  void pre(const Call& call) {
    call.field("left", call.argument<0>());
    call.field("right", call.argument<1>());
  }

  void post(const Call& call) {
    call.field("sum", call.result());
  }
};

Start the target in terminal one with debug information and a predictable function entry. Keep the target running throughout the session.

bash
c++ -g -O0 -fno-omit-frame-pointer -fno-pie -no-pie -Wl,--build-id target.cpp -o target
./target

In terminal two, run clang-tracer-repl from the same directory. Replace 12345 with the printed PID. You can also use %attach without a PID to open the process picker.

bash
%attach 12345
%symbols --filter "add("
%probe resolve "add(int, int)"
%probe validate "add(int, int)" --callback hook.cpp
%probe inject "add(int, int)" --callback hook.cpp --print-arguments --print-result
%collect --name "add(int, int)" --count 2 --timeout 30 --as first

Press Enter once in terminal one while %collect is waiting. The target prints 42; the retained events include the arguments and the sum. You can inspect the pair and read the result as a C++ value.

bash
%events list first
%events show first --index 1
%events calls first
cpp
auto first_call = tracer.batch("first");
first_call.at(1).result_as<int>()
bash
%detach
%quit

Stop the target with Ctrl+C. If discovery is empty, confirm the attached PID, use %modules to confirm the binary, and check that it still has its debug information. If attachment is refused, confirm the target is yours, its tracing policy permits the attachment, and no debugger already owns it.

Index debug information and prepare a probe from a binary

A module index is a SQLite file built from a Linux x86-64 executable or shared library and its matching DWARF debug information. Use it to inspect signatures, ELF symbols, and known type layouts before attaching to a process. You can also prepare a probe from the index with just the matching ELF and your callback.

Build and browse the index

Use target and hook.cpp from the first probe. Start a fresh native REPL in that directory. These commands work without a target attachment.

bash
%module index --file ./target --output target.sqlite
%module types --filter int
%module symbols --filter "add*"
%module show --symbol "add(int, int)"
%module show --type int

The symbol details include the linkage name, ELF address, return type and parameters when available. The type details report size and, for records, known fields and their offsets. Use the full signature or copy an ID from a listing when a name is ambiguous. Use --exported on %module symbols when you want only dynamic exports, such as the exported functions of a shared library. Regular functions in the first-probe executable can be indexed even when they are absent from that export list.

Omit --output to write <ELF>.tracer.sqlite. Choose a new filename when rebuilding an index. The REPL selects the index after creating it. In a new REPL, use %module use target.sqlite to select it again, or pass --index target.sqlite on an individual query.

When DWARF lives in a separate file, let the indexer find a matching debug companion or pass --debug-file FILE. For example, create a separate-debug copy of the lab binary and index that copy.

bash
cp target target-split
objcopy --only-keep-debug target-split target-split.debug
objcopy --strip-debug --add-gnu-debuglink=target-split.debug target-split
clang-tracer-module index --file ./target-split --debug-file ./target-split.debug --output target-split.sqlite
clang-tracer-module info --index target-split.sqlite

If you already have a local target attached to the REPL's own server, you can index a loaded image using %modules --details. Copy the exact path and mapping token from its output. The mapped ELF must have a build ID. If the output says build_id=unavailable, use file indexing instead.

bash
%module index --module /absolute/path/to/target --mapping TOKEN --output live-target.sqlite

An ELF without usable DWARF can still provide symbols, including exports, but preparation needs a supported signature and sufficient type information. Split DWARF units are reported as unresolved. If you see debug_file_mismatch, use the debug file from the same build.

Generate declarations and install the indexed probe

Back in the REPL, select the original index. Emitting headers is optional. It writes declarations.hpp, views.hpp for supported read-only field access, and manifest.json. The final command below prepares a package using the generated files and verifies them against the selected index entry.

bash
%module use target.sqlite
%module emit --symbol "add(int, int)" --output recovered-add
%probe prepare "add(int, int)" --module-index target.sqlite --module ./target --generated recovered-add --output prepared-add

Leave out --generated to let the preparer generate the same declarations internally. The package binds to the indexed ELF build and embeds the declarations it needs. Keep the package with your callback and use the same binary for the live step. If the application is rebuilt, index the new ELF and prepare a new package.

Run ./target in another terminal. Replace 12345 with its printed PID and use the same hook.cpp from the first lab.

bash
%attach 12345
%probe validate "add(int, int)" --callback hook.cpp --prepared prepared-add --prepared-mode require
%probe inject "add(int, int)" --callback hook.cpp --prepared prepared-add --prepared-mode require --print-result
%collect --name "add(int, int)" --count 2 --timeout 30 --as indexed
%events list indexed
%detach

Confirm that validation reports prepared_used: true. Press Enter in the target terminal while the capture waits. The POST event reports sum=42. The index and debug companion are needed to recover metadata. A completed prepared package can be reused for injection without either file.

See module index commands for all options, the native REPL walkthrough for a callback that reads recovered record fields, and the Python guide for the programmatic workflow.

Clang Tracer tutorials

Start with the first probe. The labs below use that target and callback unless stated otherwise. Start a fresh REPL for each live lab or remove the previous probe before installing another on the same function. Replace example IDs, addresses, and tokens with the values shown by your session. Create recordings and manifests in a scratch directory.

Inspect a process and a function entry

Attach to the running target, list its threads and modules, and find a verified function address. Paginated symbol listings use the next-page token with the same filter and page size.

bash
%attach 12345
%threads
%modules --details
%symbols --filter "add(" --addresses --limit 20
%memory maps
%probe entry "add(int, int)" --mapping MEMORY_TOKEN
%memory read ENTRY_ADDRESS --mapping MEMORY_TOKEN --count 16

Use the runtime address from the entry preview. Copy the first two bytes from the hex dump into the scan pattern, replacing the second byte with ?? to match any byte.

bash
%memory scan ENTRY_ADDRESS --mapping MEMORY_TOKEN --count 16 --pattern "55 ??" --limit 4

The scan matches 55 ?? only when the first byte is 55. Change it to the first byte you observed. If a token expires after a mapping change, take a new snapshot. Use the module mapping token from %modules --details to reverse-lookup the entry PC with %symbols --address ENTRY_ADDRESS --mapping MODULE_TOKEN.

Edit, validate, reload, and restore

Load the first lab's observer as a draft. Edit it in the REPL if desired, entering a complete replacement and ending with .end. Upload the validated draft.

bash
%interceptor load hook.cpp --as demo
%interceptor show demo
%interceptor validate demo --target "add(int, int)"
%interceptor upload demo --target "add(int, int)" --print-result
%probes

Save a separate updated.cpp with the field name changed from sum to new_sum. Replace PROBE_ID with the ID shown by %probes, then reload it and capture another call.

bash
%probe reload PROBE_ID --callback updated.cpp
%collect --count 2 --timeout 30 --as updated
%events show updated --index 1
%probes

The POST event now includes new_sum; the target still returns 42. Remove the active probe ID shown by %probes and detach.

Trace a function template instantiation

Save this function in echo.hpp and add #include "echo.hpp" to the first lab's target.cpp. Inside the existing newline branch, add std::printf("echo<int>(42) = %d\n", echo<int>(42)); before the flush. Rebuild and restart the target. Use the compilation database setup with the compiler used to build the target.

cpp
template <class T>
__attribute__((noinline)) T echo(T value) {
  volatile T saved = value;
  return saved;
}

Save this observer as echo-hook.cpp. tracer::ResolvedSignature lets the same callback source specialize against the type of the selected instantiation. For echo<int>, writing Interceptor<int(int)> explicitly would select the same signature.

cpp
template <>
class Interceptor<tracer::ResolvedSignature> {
public:
  void pre(const Call& call) {
    call.field("input", call.argument<0>());
  }

  void post(const Call& call) {
    call.field("output", call.result());
  }
};

Start a fresh REPL and attach using the new PID. Quote the complete selector, including the concrete template arguments and function parameters. Build a prepared package from echo.hpp to supply the concrete signature on this branch.

bash
%attach 12345
%symbols --filter "echo<"
%probe prepare "echo<int>(int)" --include echo.hpp --translation-unit target.cpp --module ./target --output prepared-echo
%probe validate "echo<int>(int)" --callback echo-hook.cpp --prepared prepared-echo --prepared-mode require
%probe inject "echo<int>(int)" --callback echo-hook.cpp --prepared prepared-echo --prepared-mode require --print-result
%collect --name "echo<int>(int)" --count 2 --timeout 30 --as echo_call
%events list echo_call

Press Enter in the target terminal while capture waits. The events show input=42 in PRE and output=42 in POST. Detach before exiting. For a member template, use the complete selector for the concrete method, including its class, template arguments, parameter list, and qualifiers.

Preview and apply bulk tracing

Preview an exact selector, save the selection as a reusable manifest, then install it as a batch. Use repeated include or exclude patterns to broaden or narrow the selection on a larger target.

bash
%trace preview --exact "add(int, int)" --save trace.textproto
%trace apply --manifest trace.textproto --callback hook.cpp
%collect --count 2 --timeout 30 --as bulk
%events stats bulk
%trace remove BATCH_ID

Trigger a call during collection. The summary should show one PRE/POST pair. To see a caller edge, have the callback call capture_stack(8, false) in PRE before applying the batch. The manifest can be previewed against another session using %trace preview --manifest trace.textproto.

Capture and inspect complete native stacks

bash
%probe inject "add(int, int)" --callback hook.cpp --stack-depth full --stack-application-only false --print-result
%collect --count 2 --timeout 30 --as fullstack
%events stack fullstack --index 0
%events stats fullstack

Trigger one call. The stack shows the entry and available caller frames, with native PC, function/module, and source location where recovered. Both phases describe the entry stack. full follows the supported unwind chain and can report a partial unwind. If a deep stack exceeds shared transport capacity, raise the managed server's --context-event-bytes and, if needed, --context-transport-memory-bytes before starting a new session. See the stack lab sources for application-only filtering and callback-side symbolization.

Capture in the background and query in C++

Use the probe with --print-result from the stack lab. Start a background range, trigger two target calls, and examine a stable snapshot. The predicate and transformation run in the REPL.

cpp
using namespace tracer_repl;
auto range = tracer.events_async(session, 4, 60);
cpp
auto snapshot = range.snapshot();
auto sums = snapshot
    | filter([](const Event& event) { return event.phase() == "POST"; })
    | transform([](const Event& event) { return event.result_as<int>(); })
    | to_vector();
for (auto value : sums) std::cout << value << '\n';
range.stop();

Expect two values of 42 when both calls have finished. Try first() to get the first optional match, take(1) to limit iteration, or enumerate() to pair each retained event with an index. %cpp load analysis.cpp can run an analysis script and %cpp reset resets only the interpreter and its capture handles. See event ranges and adaptors for further examples.

Record and replay offline

Keep the probe with --print-result active. For each recording command, trigger one new call while it waits, or read available history starting from the requested cursor. Use --after with the previous recording's last sequence to start a fresh window.

bash
%record calls.pb --count 2 --timeout 30
%record calls.db --sqlite --count 2 --timeout 30
%detach
%quit

Start a fresh REPL and load the recordings. Offline startup can still launch a private server, but replay requires no target attachment.

bash
%events open calls.pb --as framed
%events open calls.db --as saved
%events calls saved
%events export saved --format json --output calls.json

Use a typed query for POST events and read the recorded result.

cpp
tracer_repl::EventQuery query;
query.names = {"add(int, int)"};
query.phase = "POST";
auto recorded = tracer.replay("calls.db", query);
recorded.at(0).result_as<int>()

Expect 42. In a live CLI session, use clang-tracer events PID --sqlite copy.db --count 2 to copy events without consuming server history, or clang-tracer drain PID --sqlite consumed.db to persist and acknowledge the retained snapshot. See storage and recovery for loss counters, deduplication and failure behavior.

Prepare a reusable probe

Move the declaration of the first lab's add to add.hpp, include it from target.cpp, and keep the function definition in target.cpp. If your build does not produce a database, create this example compile_commands.json in the scratch directory. Replace the directory and compiler path with those of your target.

json
[
  {
    "directory": "/absolute/path/to/demo",
    "file": "target.cpp",
    "arguments": ["/usr/bin/c++", "-g", "-O0", "-fno-pie", "-c", "target.cpp"]
  }
]

Rebuild and restart the target. Generate a package with a new output directory and explicit source entry.

bash
%probe prepare "add(int, int)" --include add.hpp --translation-unit target.cpp --module ./target --output prepared
%attach 12345
%probe validate "add(int, int)" --callback hook.cpp --prepared prepared --prepared-mode require
%probe inject "add(int, int)" --callback hook.cpp --prepared prepared --prepared-mode require --print-result
%collect --count 2 --timeout 30 --as prepared_call
%events show prepared_call --index 1

Trigger one call and check for 42. require verifies that injection uses the package. Multiple --include options can bring in callback payload declarations. --cwd runs the probe command relative to another project directory, and --extra-arg passes supplemental compiler flags. Use the offline preparer from the command reference for the equivalent shell workflow. Run the prepared method lab to capture a receiver and replay a custom typed event.

Decode objects, containers, and method receivers

Run the installed typed-values example. It starts a debug target and checks record, scalar, string, sequence, and associative-container decoding. The native runtime and Development example sources must be present. Substitute the install prefix and data directory if customized.

bash
cd /usr/local/share/clang-tracer/examples/native-repl-values
./run.sh all

To map your own public record, set the local interpreter's compilation options before its first C++ input. Load the mapping and open the collection with the matching argument snapshot.

bash
%cpp options compdb build/compile_commands.json --file src/target.cpp
%cpp generate model.hpp --type app::Order --output mappings.hpp
%cpp load mappings.hpp
cpp
auto sample = tracer.batch("orders").at(0);
auto order = sample.argument_as<app::Order>(0);

Alternatively %cpp import model.hpp --type app::Order generates, caches, and loads a mapping in one step. Automatic mapping requires supported public members and an accessible default constructor. Use EventCodec<T> for construction through a factory, or argument_snapshot(0).field("id") to inspect fields without a mapping. For a method receiver, inspect receiver_snapshot() in the client and use call.self() in the agent. The typed C++ argument example covers references, pointers, headerless DWARF recovery, and opt-in application headers.

Observe shared context and thread propagation

Run the shared-context example from a configured source checkout with examples enabled. Start the server and target, then install the same observer on the outer and worker functions.

bash
cmake --build build-rhel --target shared-context-target
export CLANG_TRACER_ENDPOINT=127.0.0.1:50051
clang-tracer-server --listen "$CLANG_TRACER_ENDPOINT" > server.log 2>&1 &
server_pid=$!
./build-rhel/shared-context-target > target.log 2>&1 &
target_pid=$!
# Wait for clang-tracer list to succeed before attaching.
clang-tracer attach "$target_pid"
callback="$PWD/examples/shared-context/interceptor.cpp"
clang-tracer trace "$target_pid" 'process_request(int)' --callback "$callback" --callback-print-arguments true
clang-tracer trace "$target_pid" 'calculate_total(int)' --callback "$callback" --callback-print-arguments true
clang-tracer events "$target_pid" --context-field request_id,calls,last_result --count 24 --timeout 20
clang-tracer detach "$target_pid"
kill "$target_pid" "$server_pid"
unset CLANG_TRACER_ENDPOINT

Look for request.step events sharing the same request ID. The worker inherits context through supported pthread_create propagation and reports twice the request ID. The outer call reports the worker result plus one. For an explicit scope or a durable producer/collector journal, follow Shared context.

Command reference

See the C++17 branch reference for additional commands and options. Use the first probe for the examples below. Substitute its PID for 12345 and use actual session IDs, probe IDs, addresses, and tokens from your output.

Native REPL startup

bash
clang-tracer-repl --attach 12345 --buffer-events 8192 --cpp-arg "-I."
Option Meaning
--help Print startup usage and exit.
--attach PID, --process FILTER Attach by PID, or find a local process by filter. Choose one.
--endpoint ENDPOINT Use an existing server. Overrides CLANG_TRACER_ENDPOINT. Without either, the REPL manages a private server.
--server PATH, --agent PATH Override the executable and agent for the managed server.
--timeout SEC Default client deadline in seconds. The default is 30, with a maximum of 300.
--buffer-events N, --buffer-bytes N Total retained collection capacity. Defaults are 4096 events and 64 MiB.

Clang Tracer developer guide

Use the Python client or the native REPL facade to control a session. A callback runs inside the application, while an event is serialized and owned by the receiving client. Keep pointers, references, stack views, and context state within the lifetime of the callback. Use an event snapshot when the data needs to survive the call or travel to another process.

Layer Responsibilities
Client Select a target, resolve a callable, validate source, install and remove probes, stream or persist events.
Server Verify target identity, read ELF and DWARF, validate the ABI, coordinate injection, retain events and report loss.
Agent Run the JIT-compiled callback in the target and export captured data through a bounded transport.

See the C++17 branch reference for additional APIs. See the user guide for installation and the first callback, and the tutorials for complete workflows.

Python client API

The package exports Client, EventStream, ServerProcess, ServerStatus, messages (Tracer Protobuf types), and context (context transport Protobuf types). Operations return generated messages unless the table specifies a different type. RPC failures raise grpc.RpcError; argument and local storage failures raise normal Python exceptions. The client applies deadlines without automatically retrying mutations.

Agent callback API

For a typed callback, define one top-level explicit specialization of Interceptor<Signature> with either or both of pre(const Call&) and post(const Call&). Write the original function type as R(Args...), for example int(int, int), or use tracer::ResolvedSignature to reuse the type recovered from DWARF or a prepared package for the selected target. The callback compiler supplies the primary template, checks the specialization against the target, and exposes its argument and result types through Call. For a supported non-static method, the selector identifies the class and method qualifiers. The signature lists the return and explicit parameter types, and call.self() provides the receiver separately.

Hooks can return void or a long long callback value carried in the event. The original function still receives its arguments and returns its own result. Existing plain class Interceptor callbacks remain supported. Raw-symbol callbacks can use the entry-only extern "C" long long trace_callback(const TraceContext&) API.

The tracer compiles callback source with the effective target flags and checks the supported calling convention. The callback runs on the calling application thread. Keep work bounded and avoid retaining borrowed objects or invoking the probed entry recursively.

Compatibility details

The SDK compiler can parse C++20 while the target standard library predates parts of that library. include/tracer/compat.hpp selects standard std::span when available and otherwise provides a dynamic-extent view, plus compatibility helpers for byte views, bit_cast, countr_zero, construct_at, string prefix/suffix/membership checks, bit predicates, sequence erasure, and remove_cvref_t. Define TRACER_FORCE_COMPAT_LIBRARY=1 when compiling compatibility checks to exercise the project fallback even with a newer host library.

Runtime paths include both lib and lib64 in the scratch dependency prefix, the SDK's x86_64-1a-linux-gnu/lib64, and its sysroot lib64. Executables use the SDK loader explicitly. This keeps the binaries and shared libraries tied to the intended older runtime instead of depending on whichever loader happens to be first on the host.

The loader validates actual ELF SONAMEs and mapped paths, including older libc-2.23.so and libpthread-2.23.so filenames. For an application without libdl loaded, bootstrap uses the matching libc's private loader entry points. Runtime calls use the canonical mapped module path and load bias, with live entry-instruction checks for the loader and pthread entry points. GNU build IDs and binary rebuild polling are not required. A second shared probe can normalize only this session's verified existing pthread detour.

The SDK's libc process-vm wrappers are stubs; native memory reads/writes use the supported x86-64 kernel syscalls directly. The running kernel must still support the tracer's existing ptrace and process-vm operations; the SDK name does not establish compatibility with a Linux 2.6.32 kernel.

The private standard-library image uses the SDK's exact static archives, retains only available helper roots, and also supplies GCC 8's out-of-line character allocator constructors. Sealed gthread markers are bound privately; an attempted actual key creation traps. The runtime checks allow either the verified libc forwarding mutex stubs or the separate pthread implementation. They continue rejecting application interposition. Native state/exception RTTI remains enabled; only the LLVM memory-manager/importer translation units match the SDK LLVM build's disabled RTTI.

Lifecycle fingerprints use version 2: module-local LLVM attribute-group numbers are normalized while actual function, dependency and call attributes remain part of the fingerprint. Unrelated template instantiations can no longer split an otherwise identical scope generation. Quoted #number data and semantic attribute changes still distinguish generations.

Embedded compilation disables automatic host C++ include discovery and uses the native compiler's recorded include roots. This applies to private owner activation, SDK agent callbacks, and analysis-test compilation; a newer host GCC installation cannot supply optional headers missing from the SDK library. For example, GCC 11's <span> must not be combined with GCC 8's type_traits.

ELF validation checks complete file-backed PT_LOAD ranges by canonical path, permissions and file offsets, including segments that begin inside a merged mapping or span several mappings. Distinct complete load biases remain ambiguous and are rejected. Missing mappings and incomplete segment coverage remain errors. Native stack caches are reset for a new session after prior callbacks drain; adding probes within the same session reuses those caches.

The controller must map the same runtime ELF files as its target. Use the SDK-built controller with the original SDK-runtime target. The installed modern agent cannot run in that older runtime, and loading an SDK agent's old libdl/pthread into a modern libc process is not a valid control. Benchmarks therefore compare the same GCC 8.5 workload and shared library under each build's matching runtime. Their differences include compiler/library and dependency effects; they do not isolate just the compatibility helpers.

Legacy libc lacks the newer dedicated main-call wrapper. Busy-main admission therefore requires the exact ELF main function and a direct startup chain. If that leader is blocked in another syscall, an eligible existing worker can host injection. A sleeping worker retains the original interrupted-sleep policy; a directly started pthread worker in userspace must have bounded application CFI ending at exact start_thread in the mapped SDK libpthread.so.0, then exact __clone in the mapped libc. No arbitrary blocked syscall becomes an injection host. Worker TLS and the separation between the process PID and host TID are validated. Unsupported all-blocked and external job-stop cases report FAILED_PRECONDITION after safe release, without false shutdown cleanup errors. A fully stripped busy executable without that proof is rejected; idle attach remains available. The legacy stripped-admission regression checks that rejection and subsequent progress, while the modern-runtime regression still checks successful stripped busy-main admission.

Entry instruction relocation retains its existing restrictions. The separate signature Interceptor implementation adds ABI-proven object forwarding; the SDK profile alone does not establish GCC 8 by-value class ABI evidence or arbitrary RIP-relative entry relocation. Positive test fixtures use stack locals before global accesses so compiler PIE defaults do not turn them into tests of that separate entry-relocation limitation.

Launch a local application

Build the application with the installed C++17 <tracer/launch.hpp> header and add a checkpoint at the start of main, before starting threads or calling the code you want to trace. It returns immediately on an ordinary run. Treat a failed checkpoint as a startup failure.

cpp
#include <tracer/launch.hpp>

int main() {
  if (!tracer::launch::wait_for_resume())
    return 125;
  return run_application();
}

Use these commands in the native REPL with its private Linux x86-64 server. %launch selects the attached session and holds the application at the checkpoint while you install probes.

%resume
%terminate

The earliest traceable work is the first eligible call after the checkpoint. The loader, global constructors, and any earlier application code have already run. Repeat --arg for arguments and --env NAME=VALUE for overrides to the inherited environment. Relative paths are resolved from the REPL's working directory. Standard input defaults to /dev/null. Use --stdout NEW_FILE and --stderr NEW_FILE to choose output files. The REPL reports the paths and otherwise creates private log files. Existing files are protected from overwrite.

--timeout bounds the wait for the checkpoint in seconds. It defaults to the REPL timeout, which also applies separately to attach. The REPL retains ownership after detach and terminates any remaining owned children on exit. Use %status to list owned targets and reap any that have already exited. Only the launched process is managed.

If an attach reply fails or times out, the operation may still finish on the server. Call a registered function in the paused target

Register each callable at the startup checkpoint. The application compiler checks the function pointer's argument and result types. The name is an exact match to the name you register and can distinguish overloads.

#include <tracer/launch.hpp>

int main() {
  using tracer::launch::named_call;
  if (!tracer::launch::wait_for_resume(named_call("app::scale", &scale)))
    return 125;
  // Continue normal application startup.
}

Pointers, references, objects, variadic functions, and functions with an implicit receiver are outside this interface.

Calls require a target launched by this REPL with a registered checkpoint.

Use --timeout SECONDS to bound how long the REPL waits. Timeout or interruption leaves the call pending and it may continue running. Use %call-result [--timeout SECONDS] to collect its reply. Capture local syscalls or CPU samples

Attach to a running Linux x86-64 target using the REPL's own local server, then choose a capture:

%sample cpu --timeout 2 --count 256

%syscalls reports separate entry and exit records with the syscall number and the raw kernel return value on exit. %sample cpu reports user-space instruction addresses at roughly one sample per 10 ms of scheduled CPU time. Each record carries the process ID, thread ID, and a monotonic nanosecond timestamp on the same clock as probe events. Use a current mapping snapshot and %symbols --address to look up a sample address.

The command releases its kernel resources before printing records in timestamp order. It stops on timeout, the record limit, Ctrl+C, or the exit of all monitored threads. The defaults are two seconds and 256 records, with ceilings of 60 seconds and 8192 records.

The summary reports kernel loss, throttle notifications, and samples discarded at the requested limit separately. Kernels with a perf loss counter include loss still pending at shutdown. On older kernels, loss_accounting=records counts loss notifications the kernel wrote to the ring. Collection boundaries, loss, and the record limit can leave individual syscall entries or exits without a partner. These pilot records are printed by their capture command.

Syscall capture reads the raw syscall tracepoint IDs and formats from tracefs and opens the events through perf for each target thread. It needs tracefs read access and permission to open those events. CPU sampling uses a user-space perf task-clock event and can work under a policy that denies syscall tracing. Both modes report permission failures directly. Perf events allow the target threads to continue running. Background collection returns immediately so the prompt remains usable:

cpp
auto live = tracer.events_async(session);
// Enter other REPL commands while collection continues.
for (const auto &event : live) tracer.print(event);
auto data = live.snapshot();
live.running();
live.error();
live.stop();

Each loop visits a stable snapshot of currently retained events, without waiting for new arrivals or consuming them. Later loops can include the same events. snapshot() returns a Collection with received/evicted counters and completion, cancellation and timeout flags. Stream failures appear in error() in either mode; partial results remain inspectable. events_async(session, 100, 10) stops at 100 events or 10 seconds; zero count/timeout means no corresponding limit. Synchronous counts and timeouts must be positive. Both modes use C++17, without coroutines or C++20 ranges.

A range reserves the remaining shared event-count and byte budget. While it is retained, another capture may have no room; release all copies of the range (for example, with %cpp reset) to free that reservation. Snapshots can retain their owned events beyond that point. The oldest events are evicted at the budget limit. Stopping preserves the range and its reservation. The last range copy's destruction, session detach, disconnection and console shutdown cancel and join its worker. Workers never execute user C++ or print into the prompt. The controller/facade remains a foreground API; use these range handles rather than calling the facade from user-created threads.

Use %help api EventRange for the range API. Existing tracer.collect(...) and named collection commands retain their behavior.

C++17 collection adaptors

Use %help api adaptors for an overview, or look up an individual operation with %help api drop, %help api filter, or any other adaptor name.

take, drop, filter, take_while, drop_while, transform, stride, enumerate, reverse, to_vector, and first are available directly in the REPL. They also work with Collection values from collect, batch, and snapshot:

cpp
auto events = tracer.events(session, 100, 10);
for (const auto& e : events | take(10)) tracer.print(e);
auto is_post = [](const auto& e) { return e.phase() == "POST"; };
for (const auto& e : events | filter(is_post) | take(10)) tracer.print(e);
for (const auto& e : events | drop(5) | take(10)) tracer.print(e);
auto early = [](const auto& e) { return e.sequence() < 50; };
for (const auto& e : events | take_while(early)) tracer.print(e);
auto first_post = events | filter([](const auto& e) {
  return e.phase() == "POST";
}) | first();
if (first_post) tracer.print(*first_post);
auto names = events | transform([](const auto& e) {
  return e.function_name();
}) | to_vector();
for (const auto& [index, e] : events | stride(2) | enumerate()) {
  std::cout << index << ": " << e.function_name() << std::endl;
}
auto newest_first = events | reverse();
auto tail = events | drop_while([](const auto& e) {
  return e.sequence() < 50;
}) | to_vector();

take(n) returns at most the first n events; drop(n) skips the first n; filter(predicate) keeps matching events; take_while(predicate) stops at the first non-match. first() is a terminal adaptor returning an owned std::optional<Event>, empty when there is no match. Counts must be nonnegative. Predicates are evaluated lazily during iteration, and pipe order matters: filter(p) | take(10) takes ten matches, while take(10) | filter(p) tests only the first ten events. take(0) does not evaluate predicates.

Declare predicates before using them in a top-level REPL loop, or store the pipeline in a variable first. Clang Interpreter can crash while mangling an inline lambda inside a top-level loop; ordinary compiled C++ accepts it.

drop_while(p) skips only the initial matching prefix. transform(f) lazily projects each event into an owned value, such as its name, sequence or typed argument. stride(n) selects every nth element, starting with the first; n must be positive. enumerate() pairs each element with a zero-based index in the current pipeline. to_vector() materializes the selected values into an owned vector; reverse() materializes a vector in reverse order. These two operations evaluate their input immediately. Materialized results and views can be piped into further adaptors. Exceptions from predicates/projections propagate on the foreground thread.

Views own their input: lvalue collections are copied and temporaries are moved, so stored pipelines remain valid. An event-range view retains its collector handle and takes a fresh, non-consuming snapshot at each loop's start. Thus live | take(10) inspects up to ten currently retained events; it does not wait for ten new arrivals or limit background collection. Use tracer.events_async(session, 10, 5) to limit collection itself. Other C++ code can include event_ranges.hpp and use the tracer_repl namespace explicitly.

All named collections share the configured event-count and Protobuf resident allocation budget (defaults: 4096 events, 64 MiB, plus bounded container overhead). A collecting ring evicts its oldest events when full and reports local evictions separately from agent/server loss counters. Existing named collections reserve their capacity; clear them to make room. C++ snapshots keep their own shared references and can retain events after the console releases them. Collecting again under the same name releases that collection before receiving new events. Offline replay requires an unused name or an explicit %events clear first, so a corrupt recording cannot overwrite an existing capture.

Detail inspection shows typed arguments/results, receiver fields, stack frames, and raw metadata. %events stack NAME --index N prints the capture status and each retained stack frame directly, including frames from replayed events. In C++, event.stack() returns an owned vector of frames in capture order. It is empty when the event has no stored frames.

auto event = tracer.batch("batch").at(0);

Shared-context invocation/task identities remain available in event details. Loss statistics sum the latest observed cumulative agent counter per probe and server counter per server lifetime, without counting repeated samples twice. Histogram labels are inclusive nanosecond ranges, with empty buckets omitted and a final bucket for one second or longer. Durations measure the elapsed interval between the two trace timestamps, including tracing overhead.

Caller edges count calls with evidence of the direct native caller in either phase's entry stack. By default, %record uses four-byte little-endian lengths and Protobuf TraceEvent frames, with a 32 MiB per-frame limit. The prelude provides tracer and a selected-session reference named session. Copying session makes a handle that retains that server/session identity; later selection changes do not redirect it. Detached/stale handles fail before tracing operations. The facade also provides attach, inject, and detach. The interpreter initializes only for C++ input, so command-only startup does not initialize Clang.

Bare void calls work with or without a trailing semicolon; the console works around Clang's void value-printing behavior without executing calls twice. Every submitted C++ cell is checked in a disposable clang-tracer-repl-check process before the live interpreter parses or executes it. The checker parses the accepted cells in their original order without executing them, preserving macro state and incremental source context. A rejected cell cannot change live variables or macros, and completion and expressions remain available without %cpp reset. The checker stops at the first compiler error. Programmatic tracing

The repository's examples/python/README.md describes runnable programs for attachment, probes, live streams, binary recordings, and server lifecycle, including commands for the native example target.

python
from pathlib import Path
from clang_tracer import Client

with Client("127.0.0.1:50051") as tracer:
    session = tracer.attach(12345)
    probe = tracer.inject(
        session.id,
        "Calculator::add(int, int)",
        Path("interceptor.cpp").read_text(),
        stack_depth=24,
        print_arguments=True,
        print_result=True,
    )
    try:
        for event in tracer.collect_traces(20, session_ids=[session.id], timeout=10):
            print(event.sequence, event.phase, event.call_id, event.stack)
    finally:
        tracer.remove_probe(session.id, probe.id)
        tracer.detach(session.id)

inject() resolves the C++ selector on the server using DWARF, then submits the resulting ProbeSpec with the interceptor source. It requires the additive ResolveProbe RPC introduced with this client. Rebuild/reinstall the native server from this revision before using it; an older server returns gRPC UNIMPLEMENTED. Existing RPCs remain compatible with older servers.

Injecting a target already hooked in the same session replaces that probe with a new ID. Compilation failure leaves the existing hook active. A successful replacement restores and drains the old hook before installing the new one, so there is a brief interval without tracing. The existing 32 retained-probe limit also counts replaced versions. Rebuild the server and agent together for this behavior; an already loaded older agent requires restarting the target.

The console decodes shared-state payloads using each event's bundled schema and shows field values, including strings, nested records, and containers, beneath the payload summary. Invalid payloads produce a diagnostic, and large values are visibly truncated. Pointer arguments still display their captured address.

Callback source is transmitted by value. Optional include_headers, compilation_database and callback_package_path refer to paths on the server host. Package location is optional; pass it when the source belongs to a retained shared-context package. Omitting it follows the native service's isolated source-lineage behavior. The client never assumes a local callback path exists remotely.

compile_options is an ordered list of compiler arguments for resolving and compiling the callback. Pass it to either resolve_probe() or inject(); inject() carries the same options through resolution and AddProbe, and add_probe() preserves options already stored in the ProbeSpec. Include directories and any header/compilation-database paths are interpreted on the server host. For example, use compile_options=["-std=c++17", "-I/opt/app/include"] when the target headers live under /opt/app/include on that host. Supported options cover include paths (-I, -isystem, -iquote, -include), defines and undefines (-D, -U), language standard (-std=), common warning, optimization and debug flags. A compilation database can also supply its matching --sysroot and --gcc-toolchain settings; target triples are checked against the engine. Unsupported compiler flags are rejected before preflight or installation. Forced -include headers are processed in source order during preparation; preflight does not execute their global initializers. Standard-library types such as std::string use the real target headers, and their ABI macros (including _GLIBCXX_USE_CXX11_ABI) must match the target build. For example, a std::string callback validated against a target built with the new libstdc++ ABI must keep _GLIBCXX_USE_CXX11_ABI=1. Object arguments and by-value results are exposed as borrowed references during the callback; a returned object is available only during POST.

Use validate_probe() to check callback source without installing a probe:

python
report = tracer.validate_probe(
    session.id,
    "Calculator::add(int, int)",
    Path("interceptor.cpp").read_text(),
    compile_options=["-std=c++17", "-I/opt/app/include"],
    level="compile",
)
if not report.success:
    for diagnostic in report.diagnostics:
        print(diagnostic.stage, diagnostic.file, diagnostic.line,
              diagnostic.column, diagnostic.message)

level="syntax" checks parsing and reports source diagnostics. The default, level="compile", also generates and checks the complete callback wrapper and its method bindings. Validation does not install or execute callbacks and does not run callback global initializers. The report includes success, diagnostics with severity, stage and source location, and the ordered compiler options supplied for the callback. The console exposes the same operation as probe validate SESSION SELECTOR --callback FILE --level compile; add repeated --compile-option ARG flags for ordered compiler arguments. Validation requires the server's additive ValidateProbe RPC.

resolve_probe(session_id, selector, ...) returns the complete inferred spec without installing it. add_probe(session_id, spec) accepts a generated clang_tracer.messages.ProbeSpec, preserving access to every advanced field and the explicit low-level ABI mode. list_sessions(), remove_probe() and detach() return generated messages too. The generated stubs and all context transport messages are available under clang_tracer.proto; ContextTransport is the native producer/collector protocol, rather than an additional public tracing control API.

Unary RPCs default to a 30-second deadline, configured with Client(timeout=...). Errors retain their original grpc.RpcError status and details. The client performs no implicit control retries because operations can mutate targets.

Discover functions and methods

For an attached session_id, list callable selectors on the tracing host:

Returned selectors can be passed to resolve_probe() or inject(). Discovery reads mapped application ELF/DWARF images on the server; it requires no target source files on the client. Functions without supported debug signatures are omitted. Listing a function does not bypass probe admission checks.

Receiving and recording traces

python
with Client() as tracer:
    with tracer.watch_events([session_id], after_sequence=last_sequence) as stream:
        for event in stream:
            consume(event)
            last_sequence = stream.after_sequence

Live streams have no deadline unless timeout is supplied. Call stream.close() from another thread to cancel a blocked read, or leave its context manager. Client.close() cancels streams on its owned channel. Empty session filters subscribe to every session; pid optionally filters by process. Every event retains stack frames, shared-context schema/payload bytes, drop counters and PRE/POST correlation fields.

The optional names filter matches emitted event names and full C++ function signatures. For example:

python

        session_ids=[session_id],
        names=["snapshot", "Calculator::multiply(int, int) const"],
        timeout=10,
    ) as stream:

            print(event.function_name, event.context.event.name)

Names match exactly, including case, spaces and signature qualifiers. A match against either name is sufficient; session and PID filters must also match. The displayed function_name normally comes from the resolved C++ signature; when that signature exceeds 4096 UTF-8 bytes, the server uses its linkage symbol. Omit names to receive all names. collect_traces() and record_traces() accept the same option and count matching events. Name filtering requires an updated server; the client reports an error if a server returns events outside the requested names. Events retain their global sequence numbers, so filtered results can have expected sequence gaps.

The server's history is bounded. A stale cursor produces OUT_OF_RANGE; the client does not silently reset it or reconnect. Watch the event drop counters and per-probe sequence gaps when assessing completeness. Stream deadlines also raise their gRPC error, including during collection.

collect_traces(count, ..., timeout=30) retains at most count messages in a list. For larger recordings use:

        "capture.pb",
        100_000,
        session_ids=[session_id],
        timeout=120,

Recordings contain repeated four-byte unsigned little-endian lengths followed by serialized TraceEvent bytes. Recording creates the file exclusively and streams directly to disk. On interruption or RPC failure it preserves completed records in the partial file and cancels the subscription. The exception still propagates; partial data is not reported as a successful complete recording.

Launch, status and shutdown

Both the API and console can launch and own a local native server:

python

    tracer.start_server()

Set context_event_bytes=25165824 and context_transport_memory_bytes=234881024 in start_server() for 24 MiB shared events. The console equivalent is server start --context-event-bytes 25165824 --context-transport-memory-bytes 234881024.

ServerProcess is also exported for standalone process management. Startup checks that the endpoint is unused, launches without a shell, and waits for a successful ListSessions RPC. Startup output is captured for failure diagnostics. status() distinguishes service readiness from ownership of a child process. Owned channels keep their connection state separate and use bounded reconnect delays, so failed status checks before launch cannot leave startup waiting on another client's connection backoff. Readiness waits for the RPC to succeed; printing a listening address alone does not establish readiness. A startup timeout includes the last readiness RPC status. Caller-supplied channels retain their own transport settings, and mutating RPCs are not automatically replayed. The startup timeout covers both readiness phases; graceful target restoration after a failure can take additional time. If the caller's channel cannot become ready after launch, the client retains ownership so it can still shut down the managed server.

Shutdown sends SIGTERM to the owned child and waits for the native server to detach sessions and restore probes. A nonzero exit is an error. If graceful shutdown times out, ownership remains available for a later retry; the manager does not force-kill a server while it may still be restoring targets. Closing the client or exiting the console also shuts down its managed server. The child has its own process session, so terminal Ctrl-C only interrupts the console. Shutdown retries wait for the same cleanup without sending another signal.

An independently running or remote server can be queried with status(), but cannot be terminated through this manager. There is no remote shutdown RPC in the existing service. A console connection does not adopt an existing server. Sessions on an external server remain attached until explicitly detached.

Configure retained history

sh
clang-tracer-server --listen 127.0.0.1:50051 \
  --event-history-limit 16384 \
  --context-history-limit 512 \
  --context-history-bytes 67108864

The server retains a bounded shared history. This change keeps its defaults and adds startup flags --event-history-limit, --context-history-limit, and --context-history-bytes (serialized context bytes, not total process RAM). All limits are positive integers; lowering a context limit must not block tracing. An event larger than the context-byte budget is dropped. This can include PRE/POST events from a context-enabled probe. Limits apply to the shared server history, not separately to each session, and cannot be changed on a running server.

Save or drain

sh

clang-tracer events 12345 --sqlite capture.db --count 100 --timeout 30
# Drain the current retained snapshot for every session.
clang-tracer drain --sqlite capture.db
# Continuously save and consume events for one PID.
clang-tracer drain 12345 --sqlite capture.db --listen --timeout 60

The console uses the selected session by default; without a selection it drains all sessions. --session ID, --pid PID, --name NAME, and --after CURSOR narrow the capture. Ctrl-C returns to the prompt. Native drain defaults to all sessions and supports PID and after filters. --listen polls every 100 ms when the snapshot is empty; it is a foreground operation.

clang-tracer drain --sqlite capture.db saves a snapshot of retained events and acknowledges exactly those events after SQLite commits. --listen repeats this until interrupted; --count and --timeout bound the operation. An optional PID narrows the drain. The console supports drain capture.db [--listen] [--count N] with the existing session, PID, name and after filters. record capture.db N --sqlite and native events PID --sqlite capture.db save without consuming.

Reads never reserve or delete events. Acknowledgements carry a random server lifetime identity and exact sequence IDs. Snapshot continuation pins that same identity. Concurrent drains are idempotent in one database, but different databases may both save a batch read before either acknowledgement. Storage failures do not acknowledge events. An acknowledgement failure may leave a committed batch; retrying into the same database deduplicates it. Draining consumes history for every client; stale watchers receive OUT_OF_RANGE. Existing overflow and transport loss remain possible; recording does not provide lossless capture.

SQLite format and failure handling

Both writers use trace_events with full Protobuf payloads and queryable identity, process, thread, phase, function and drop-counter columns. Unsigned 64-bit values are decimal TEXT, avoiding SQLite signed-integer overflow. The primary key is (server_instance_id, sequence); server restarts must not collide. Each bounded batch commits before acknowledging. SQLite stays on the client host and can grow until storage is full. WAL uses FULL synchronous commits. The database path must name a persistent file; empty paths and :memory: are rejected. Both writers create a missing database and append to an existing one.

Open the recording from the native REPL with %events open capture.db --as saved. Use tracer.replay("capture.db", query) to select events by function or custom event name, phase, process, or session before reading them. See Query a recording offline for examples.

Shared context

For a commented, runnable introduction, start with the two-probe worker example.

Shared context lets independently compiled class interceptors keep typed C++ state and publish a snapshot with Call::context().event(). The stream carries descriptor-backed values, so the CLI can decode fields across schema revisions without a user-maintained JSON schema.

Declare and use state

Include the public tracer/context.hpp header in callback sources that declare context types. Mark each state with its scope and inject it through the interceptor constructor:

cpp
#include <string>
#include <vector>
#include <tracer/callback.hpp>
#include <tracer/context.hpp>

struct RequestScope {};

struct RequestState : tracer::shared_state<RequestScope> {
  std::string request_id;
  std::vector<std::string> items;
};

struct Interceptor {
  Interceptor(tracer::State<RequestState>);

  void pre(const tracer::Call&, RequestState& state) {
    state.request_id = "request-42";
    state.items.push_back("book");
  }

  void post(const tracer::Call& call) {
    auto& state = call.context().get<RequestState>();
    call.context().with<RequestState>([](RequestState& value) {
      value.items.push_back("shipped");
    });
    call.context().event("request.completed");
  }
};

State<T> declares a constructor dependency; the engine constructs and binds the state before the hook and can inject T& into a hook parameter. Use get<T>() for direct typed access or with<T>(visitor) for a scoped visitor. shared_state<Scope> identifies state shared by compatible calls and probes; state<Scope> identifies ordinary scoped state. Synchronization for ordinary state remains the callback author's responsibility. Shared state access follows the engine's guarded access rules; do not retain references beyond the hook or visitor call.

Generated owner construction can initialize a payload from the source hook's root call with T(const tracer::ScopeInit&); init.root_call() exposes that call only during initialization. For generic declarations, use call.context().init_scope<Scope>(), the typed-payload overload init_scope<Scope>(payload), and end_scope<Scope>(). Scope initialization and teardown are runtime-managed; they do not require a user token or global map.

Call event(name, max_items) to publish a complete snapshot of the visible state. The default item cap is 100; the accepted range is 0 through 4096. The serialized event payload and its metadata have a 256 KiB capture limit. Descriptor sets are admitted separately, with a 1 MiB limit per descriptor set; they do not consume that event-payload limit. Admission is atomic: if the event or any required descriptor cannot fit its respective bounded budget, the event is dropped rather than partially published.

Thread propagation

When a supported pthread_create call happens in an active application hook, the native adapter captures the full eligible context-task chain and attaches it to the new thread. This also covers libraries that create threads through pthread_create; callbacks do not need to wrap the call or pass a token. Accepted child work retains its state and probe leases until it completes, so removing the last related probe may wait for that work to drain. Propagation is limited to application execution. The adapter fails open to the original pthread_create call when it cannot safely admit propagation, and records a bounded diagnostic. Native pthread_create detouring is supported only when the target's CET status is verified inactive for all threads; active or unverified CET configurations are rejected for this propagation mode.

Events and field queries

Context events are included in the regular events and WatchEvents output. The viewer discovers the union of field paths present in retained descriptors for a state family by default. Select one or several dotted paths with --context-field; a path missing from a particular revision is shown as <missing> rather than converted to a different field:

sh
./build/clang-tracer events "$PID" --count 20
./build/clang-tracer events "$PID" --count 20 \
  --context-field request_id,items.sku

The output labels each value with its state family and schema revision. Event arguments and results remain hidden unless the callback's print options request them. A requested native entry stack is retained and displayed with the same Watch event.

Package lineage

The engine assigns each recognized callback owner package a random 16-byte lineage UUID and persists it in engine-managed package metadata. Callback files in the same recognized package reuse that lineage; edits and file renames do not derive a new identity from source text, path, type spelling or build ID. The package root is located from existing retained metadata or the nearest .git / compile_commands.json root, with the callback directory as the standalone fallback. Imported definitions are associated with their defining package. The UUID is internal; there is no public source-origin UUID option.

If a package cannot be verified or its metadata cannot be retained, the engine isolates that source with a distinct lineage and reports a diagnostic. This prevents unrelated or unverifiable packages with identical C++ names from sharing state. The package metadata is separate from callback contents and is created only during probe setup.

Build and recording

Shared context is supported by the Linux x86-64 build profile. It requires the matching static libstdc++.a and libgcc_eh.a selected by the build compiler. CMake packages that exact standard-library runtime in the sealed libclang_tracer_context_stdlib.so support image. Complete native C++ interceptor example

The target below uses ordinary C++ declarations, with no compiler attributes. LLVM reads the running binary's DWARF; Clang constructs a checked receiver type so call.self() reads object fields without target source or a copied class. Control and events remain gRPC and binary Protobuf; the CLI displays readable events.

Run on Linux x86-64 with a configured tracer build. The existing example target uses -g and -O0 in CMake, without enabling executable symbol exports. target.cpp

The target prints its PID, arguments, member fields, and original results.

cpp
#include <cerrno>
#include <csignal>
#include <cstdio>
#include <ctime>

#include <unistd.h>

namespace {
volatile std::sig_atomic_t keep_running = 1;
int initialization_count = [] {
  std::puts("INITIALIZER fired");
  std::fflush(stdout);
  return 1;
}();

void stop_target(int) { keep_running = 0; }
} // namespace

int add(int left, int right) {
  volatile int saved_left = left;
  volatile int result = saved_left + right;
  return result;
}

class Calculator {
public:
  int bias = 7;
  mutable int calls = 0;

  int multiply(int value, int factor) const {
    ++calls;
    volatile int saved_value = value;
    volatile int result = saved_value * factor + bias + calls;
    return result;
  }

private:
  int hidden = 99;
};

int main() {
  std::signal(SIGINT, stop_target);
  std::signal(SIGTERM, stop_target);

  const Calculator calculator;
  int iteration = 1;
  std::printf("TARGET pid=%ld\n", static_cast<long>(::getpid()));
  std::fflush(stdout);

  while (keep_running != 0) {
    const int left = iteration;
    const int right = 10 + iteration;
    const int factor = 2 + iteration;
    const int sum = add(left, right);
    const int product = calculator.multiply(left, factor);
    std::printf("CALL init=%d left=%d right=%d add=%d value=%d factor=%d bias=%d calls=%d multiply=%d\n",
                initialization_count, left, right, sum, left, factor,
                calculator.bias, calculator.calls, product);
    std::fflush(stdout);

    iteration = iteration == 5 ? 1 : iteration + 1;
    timespec delay{0, 200'000'000};
    while (keep_running != 0 && ::nanosleep(&delay, &delay) != 0 &&
           errno == EINTR) {
    }
  }

  std::puts("TARGET stopped");
}

method.cpp

The method interceptor reads bias and calls before and after multiply runs.

cpp
// Clang constructs the receiver type from binary DWARF; no target source is
// needed.
class Interceptor {
public:
  void pre(const Call &call) {
    call.argument<int>(0);
    call.argument<int>(1);
    call.field(call.self()->bias);
    call.field(call.self()->calls);
  }

  void post(const Call &call) {
    call.argument<int>(0);
    call.argument<int>(1);
    call.field(call.self()->bias);
    call.field(call.self()->calls);
  }
};

call.self() is a const-qualified Calculator pointer reconstructed from DWARF. pre() sees calls before the method increments it; post() sees the new value. Argument 0 is value, argument 1 is factor; their names come from debug data. call.field(call.self()->bias) infers bias from the callback's Clang AST. There are no string labels in these interceptors. POST carries the original result automatically. Private/protected fields remain inaccessible.

DWARF-typed class-instance arguments

call.argument<Index>() exposes any supported argument position using the type resolved from DWARF. No Order/Coupon declaration or target header is needed in the callback. This example mixes two different class types, a by-value Order, references, a pointer, an integer, and a double.

Index in total Target type Callback access
0 Order& const auto& order = call.argument<0>()
1 double auto fee = call.argument<1>()
2 const Coupon& const auto& coupon = call.argument<2>()
3 Order const auto& sample = call.argument<3>()
4 int auto count = call.argument<4>()

Views of class arguments are const-qualified. Reference and pointer views refer to the actual argument object; POST sees its updates. A by-value argument exposes the wrapper's entry snapshot, which remains unchanged in POST even if the callee modifies its own copy. call.result<T>() exposes the original result in POST.

Field paths are inferred from the originating argument, such as order.quantity and sample.quantity; the callback's local alias need not match the target name. Local scalar captures infer their labels too. Transport remains gRPC/Protobuf.

target.cpp

cpp
#include "order.hpp"

#include <cerrno>
#include <csignal>
#include <cstdio>
#include <ctime>
#include <unistd.h>

// The tracer obtains these argument types solely from the binary's DWARF.
double total(Order &order, double fee, const Coupon &coupon, Order sample,
             int count) {
  volatile double saved_fee = fee;
  const double result = order.quantity * order.unit_price + saved_fee -
                        coupon.amount + sample.quantity * sample.unit_price;
  order.quantity += count;
  sample.quantity +=
      10; // A local by-value copy: the caller's sample stays unchanged.
  return result;
}

double pointer_total(Order *order, int extra) {
  volatile int saved_extra = extra;
  if (!order)
    return 0;
  const double result = order->quantity * order->unit_price + saved_extra;
  order->quantity += extra;
  return result;
}

namespace {
volatile std::sig_atomic_t running = 1;
void stop(int) { running = 0; }
} // namespace
int main() {
  std::signal(SIGINT, stop);
  std::signal(SIGTERM, stop);
  std::printf("TARGET pid=%ld\n", static_cast<long>(::getpid()));
  std::fflush(stdout);
  int calls = 0;
  int failures = 0;
  while (running) {
    Order order{3, 12.50};
    const Coupon coupon{2.0, 1};
    Order sample{2, 3.50};
    const double result = total(order, 1.25, coupon, sample, 2);
    const int after_total = order.quantity;
    const double pointer_result = pointer_total(&order, 3);
    if (result != 43.75 || after_total != 5 || order.quantity != 8 ||
        sample.quantity != 2 || pointer_result != 65.5)
      ++failures;
    std::printf("CALL calls=%d order_before=3 order_after_total=%d "
                "order_after_pointer=%d sample=2 fee=1.25 coupon=2 count=2 "
                "total=%.2f pointer=%.2f failures=%d\n",
                ++calls, after_total, order.quantity, result, pointer_result,
                failures);
    std::fflush(stdout);
    timespec delay{0, 200'000'000};
    while (running && ::nanosleep(&delay, &delay) != 0 && errno == EINTR) {
    }
  }
}

Optional headers and compile_commands.json

The commands above work without the target's headers, sources or build database. When a target header is available, Clang can use its original declarations:

--compdb accepts a directory or a compile_commands.json file. Clang infers the header's command from source entries using filename and directory similarity; the CLI prints which entry it selected. Supported boundary

Up to eight explicit arguments and 16 named arguments/fields per hook. Flat named class/struct types must have complete embedded DWARF and matching ordinary layout with supported scalar/builtin-pointer members. The agent constructs all argument record declarations with Clang APIs and checks type, access, size and every member offset. Any conflicting layouts fail before patching.

By-value classes require explicit DWARF pass-by-value calling-convention evidence; Clang then performs the native aggregate ABI lowering. Nontrivial/unsupported passing conventions, inheritance, virtual layout, bitfields, nested aggregate members, class results, and missing/incomplete debug information are rejected. Callback-side class construction/copying and method invocation remain rejected; the generated native wrapper may copy only the validated by-value argument. Keep views within the invocation and obey the target's object-lifetime and synchronization rules. Optional headers are not required.

Native bootstrap ABI is 13; Protobuf adds OBJECT=8 for by-value snapshot addresses. The event protocol remains version 2 and named member values remain typed scalars.

Modes and scope of this draft

  • require: use the prepared package or report why it could not be bound.
  • prefer: attempt prepared resolution, then fall back to DWARF if it fails.
  • off: use the ordinary DWARF resolution path.

The REPL automatically tries the latest package it generated for the selector and falls back to DWARF when it cannot use the package. Pass --prepared DIRECTORY to select a package in another directory or from another REPL session. Fallback happens during resolution, before the hook is installed.

Prepared packages support concrete Linux x86-64 free functions and methods. For virtual dispatch, select the override, such as Derived::run(int) const. Calls through a base pointer are captured when dispatch reaches that implementation, including calls through an adjusting thunk. A selector installs one hook at its executable entry. Typed packages retain the declared C++ signature and header layout. The declarations and build flags must describe the running function's ABI. Injection binds the package to the symbol in the mapped ELF image and checks the adapter's ABI and layouts before compiling the callback. If multiple modules define the symbol, pass --module PATH to select one.

Regenerate version 3 typed packages to obtain the standalone adapter. Generated record declarations support layout and value inspection. The current adapter generator supports namespace-scope records, enums, polymorphic bases, concrete class template specializations, and supported standard library types. Preparation checks virtual base layout and rejects types whose ABI it cannot reproduce.

Use explicit template arguments and the concrete parameter list to prepare template functions and methods, for example twice<int>(int), Handler::convert<double>(double) const, or Box<int, 5>::apply(int) const. The preparer resolves the concrete declaration without building the target. Injection requires the instance to have an executable symbol and a safe patch window in the target.

The concrete demo prepares Handler::scale(int), Handler::shift<int>(int), Handler::Nested::adjust(int), and Handler::Nested::adjust<int>(int) with the prepared_concrete:: qualifier. The native_repl_prepared_concrete test injects all four static methods after removing the application header and checks that they return 12, 6, 13, and 14 for input 4. For nested static methods, the package preserves the original symbol and callable signature. Argument and result types follow the same adapter rules as other prepared probes.

For records with application-defined copy, move, or destruction code, the standalone adapter preserves the lifetime declarations and lets the target perform those operations. Reference and by-value snapshots can capture fields from those records. For a raw pointer, the callback decides when to read the pointee and can publish an owned field payload. Use --compile-option "-fno-access-control" on injection if the callback itself names protected or private fields. Automatic snapshots already include those fields. If the adapter cannot reproduce a pointee layout, the probe can still capture the pointer address.

Shared context: one request, two probes, one worker

process_request(id) starts a worker that calls calculate_total(id), waits for it, then returns the worker's result plus one. Both functions use the same interceptor file, compiled separately for each probe. Their hooks see the same request state, including on the worker thread.

File Purpose
target.cpp Ordinary application code; no tracer dependency.
interceptor.cpp Commented state declaration and PRE/POST hooks.
example-output.txt Recorded worker and outer POST snapshots showing both APIs.

The outer PRE starts the state with calls = 1. The worker PRE changes it to 2. Each POST publishes a snapshot; the outer POST finishes the request scope. The next request starts with fresh state. std::thread uses pthread_create on this Linux profile, so propagation happens automatically.

The POST hook demonstrates two different operations:

API What it does here
call.field("hook_result", result) Adds one named scalar to this call's metadata.
call.context().event("request.step") Publishes a named snapshot of the visible request state.

The field is recorded before the snapshot. Both trace commands below enable --callback-print-arguments true, so the context event also carries the recorded hook_result field. The shared-state fields are captured by event().

native_detour_relocation executes relocated global loads, stores, immediate stores, address calculations, scalar SIMD loads and instructions with multiple references. It checks positive and negative displacements, both signed-32-bit range boundaries, memory accesses straddling the patch window, unreadable page boundaries, failed preparation without partial publication, and RX trampoline permissions. Unsupported control transfers and addressing forms remain rejected.

grpc_native_pie_integration builds tests/fixtures/target.cpp with explicit -fPIE -pie and runs the complete native integration against it. The early global store in traced_void must be relocated. The integration replaces the probe in the same session, checks events and the target's global value, and exercises detach, reattach and server-shutdown restoration.

Verified on 2 November 2026 with Clang/LLVM 21.1.8 on Linux x86_64: 20/20 CTests passed in 390.88 seconds. The exact PIE binary that previously failed at traced_void also passed the complete native integration with its SHA-256 unchanged (de71b39aec9a05bc2bbefba0f843908508048d6b8703106e5aebb9e14c30b7da). The relocation execution tests passed with AddressSanitizer and UndefinedBehaviorSanitizer; function-type instrumentation was disabled for the tests' deliberately generated machine-code entry points. Focused clang-tidy checks reported no findings in the changed source. Local evidence is retained under test-results/pie-detour-20261102/ and on linux-dev:/tmp/clang-tracer-pie-fix-20261102/.

These results cover base 60d85f8 plus this fix. During validation, main advanced to e985625 with separate event-storage changes. The full fix patch applies cleanly to that revision; the complete suite was run on the isolated base above.

Measured tracing overhead

Measurements on 30 October 2026 used an eight-vCPU Linux x86_64 VM, Clang21.1.8 and a RelWithDebInfo agent. The benchmark binary used -O2 -g -fno-inline -fomit-frame-pointer -fno-optimize-sibling-calls -fasynchronous-unwind-tables -fcf-protection=none, linked to the existing calculator fixture. The application call chain was main -> benchmark_iteration -> library_dispatch -> StackCalculator::multiply -> stack_add.

Both traced modes used the empty automatic.cpp callback. Stack mode requested 24 frames with application filtering; callback argument/result text was off. Each mode had nine rotated repetitions. Traced repetitions used 100 warmup plus 1,500 timed calls; unattached repetitions used five million timed calls. Target and its sender ran on CPU2; the server ran on CPU3. Setup, JIT compilation, warmup, text output and detach were outside the timed loop. Capture, event serialization and enqueue were included; transport draining was asynchronous.

An accepted mapping-read batching change produced the following fresh comparison:

Mode Before median/call After median/call Events lost before / after
Tracing off 9.56 ns 9.82 ns —
Tracing without stacks 6.968 us 7.268 us 0 / 0
Application-only stacks 92.094 us 85.582 us 0 / 0

Both versions received all 28,800 events per traced mode, including warmup. All 144,000 before/after application frame records matched. With the receiver stopped, the updated implementation completed 1,500 stack-enabled calls in 130.482 ms; all 3,200 events arrived after resume and immediate detach.

A subsequent positioned-read candidate was evaluated with three interleaved three-round chunks per version, preserving nine repetitions and the original mode rotation. Its stack-enabled median was 89.403 us/call versus 88.179 us for the retained implementation. Both versions again received all events. There was no reliable overall gain, so the candidate was reverted and the original source and agent restored exactly.

These are repetition averages for a small synthetic workload. Ranges overlapped and controls varied; they are neither individual-call latency percentiles nor a performance guarantee.
